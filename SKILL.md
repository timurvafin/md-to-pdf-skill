# Скилл: конвертация Markdown → PDF

## Процесс

### Шаг 1: Определить входной файл

- Пользователь указывает путь к Markdown-файлу или просит конвертировать контент из разговора.
- Если файл не указан — спросить у пользователя путь к исходному файлу.
- Если нужно конвертировать inline-контент, сначала записать его во временный `.md` файл.

### Шаг 2: Выбрать тему

Тема выбирается по типу контента или по явной просьбе пользователя:

| Тип контента | Тема | Файл |
|---|---|---|
| Техническая документация, код | `modern` | `theme-modern.css` |
| Деловые документы, отчёты | `professional` | `theme-professional.css` |
| Научные статьи, академические тексты | `academic` | `theme-academic.css` |
| Тёмный режим / чтение с экрана | `dark` | `theme-dark.css` |
| Чистый минималистичный вывод | `minimal` | `theme-minimal.css` |
| **Фирменные документы КПМ** (КП, оценки, письма) | `kpm` | `theme-kpm.css` + `template-kpm.html` |
| **Фирменные документы Эф-эс** (договоры, письма, КП от ООО «Эф-эс») | `ef-es` | `theme-ef-es.css` + `template-ef-es.html` |
| По умолчанию (если неясно) | `professional` | `theme-professional.css` |

Если тема не указана явно — автоопределение по контенту:
- Много блоков кода → `modern`
- Формальный язык, цитаты, сноски → `academic`
- Фирменные документы КПМ (КП, оценки, письма клиентам) → `kpm`
- Документы от имени ООО «Эф-эс» → `ef-es`
- Во всех остальных случаях → `professional`

### Тема `kpm` — дополнительные параметры

Тема `kpm` использует кастомный HTML-шаблон и читает YAML frontmatter из markdown:

```yaml
---
# Шапка (3 колонки: лого | заголовок | реквизиты)
header-logo: /absolute/path/to/logo.svg
header-title: "Оценка стоимости\n1 и 2 этапов дизайна сайта"
header-company: |                            # опционально, есть дефолт
  ООО «Казанская проектная мануфактура»
  ОГРН 1241600035841

# Водяной знак (большой бледный фоновый знак КПМ)
watermark-image: /abs/path/to/sign_black_rgb_mirror.png  # обычно зеркальный знак КПМ
watermark-position: bottom-right             # bottom-right | bottom-left | center
watermark-opacity: "0.03"                    # КПМ-практика 0.03 (дефолт шаблона — 0.06)
watermark-size: 2160px                       # КПМ-практика 2160px — большой «вытекающий» знак (дефолт шаблона — 200px)

# Блок подписи (внизу документа, выравнивание вправо)
signature-name: Мамаев Алексей Сергеевич     # опционально
signature-title: Директор ООО «Казанская проектная мануфактура»
signature-image: /path/to/signature.png      # опционально
---
```

Если `header-logo` не указан — шапка не рендерится. Если `header-company` не указан — используются дефолтные реквизиты КПМ. Если `watermark-image` не указан — водяной знак не показывается. Если `signature-name` не указан — блок подписи не показывается.

> ⚠️ **Размер знака — частая ошибка.** Позиция `bottom-right` откалибрована в CSS под **большой фоновый знак, вытекающий за угол листа** (`bottom: 20%; right: 10%` — в страницу попадает только его «клин»). Поэтому боевые документы КПМ используют `watermark-size: 2160px` + `watermark-opacity: "0.03"` + зеркальный знак (`sign_black_rgb_mirror.png`). Маленький размер (~200px) при `bottom-right` повиснет в середине-справа и будет выглядеть как потерянная иконка — это не баг шаблона, а несоответствие размера задумке. Если нужен реально маленький знак — берите `bottom-left` (там якорь в настоящем углу, `1cm/1cm`).

### Тема `ef-es` — фирменный бланк Эф-эс

Сделана по макету договора (`ef-es-docs/04-dogovor.html`): Inter + IBM Plex Mono (лежат в `assets/fonts/ef-es/`, OFL), акцент `#1F4FE0`. На первой странице — большая шапка (знак, «Эф-эс», слоган, контакты) и заголовочный блок; на следующих — компактная бегущая шапка со ссылкой на документ. Внизу каждой страницы — поля для визирования и `Договор № … · 01 / 02`. Полный пример — `examples/ef-es-dogovor.md`.

```yaml
---
doc-kicker: Договор                      # синяя моно-надпись над заголовком
doc-title: Договор № 2026-014            # H1; без него заголовочный блок не рендерится
doc-subtitle: на разработку веб-системы «…»
doc-city: г. Казань                      # строка «город ……… дата»
doc-date: 03 августа 2026 г.
doc-ref: Договор № 2026-014 от 03.08.2026   # бегущая шапка/футер (дефолт — doc-title)
footer-sign: [Исполнитель, Заказчик]     # «Исполнитель ____  Заказчик ____» в футере; нет ключа — нет полей
numbering: clauses                       # clauses (дефолт): разделы 01 + пункты 1.1 | sections: только 01 | none
header-tagline: Разработка веб-систем    # опционально, это дефолт
header-contacts: |                       # опционально; дефолт — info@ef-es.ru / ef-es.ru / адрес
  info@ef-es.ru
  ef-es.ru
parties-title: Реквизиты и подписи сторон   # опционально, это дефолт
parties:                                 # карточки реквизитов с линией подписи — последний раздел
  - role: Исполнитель
    name: ООО «Эф-эс»
    details:
      - {k: ИНН/КПП, v: "1660148622 / 165501001"}   # значения — в кавычках (квадратные скобки, двоеточия)
    signer-title: Генеральный директор
    signer-name: И. О. Фамилия
---
```

Правила разметки тела:
- `##` — раздел договора, получает номер `01`, `02`… Каждый абзац после `##` автоматически получает номер пункта `1.1`, `1.2` — **номера руками не писать**. Абзацы до первого `##` (преамбула) не нумеруются, списки/цитаты/таблицы — тоже.
- В таблицах номер строки пишется кодом: `` `01` `` в первой колонке — синий моно-номер; даты/сроки в других колонках — тоже кодом (`` `03.08 — 31.08.2026` ``) → тёмный моно без переноса. Числа — колонкой с выравниванием `---:`.
- Строка «Итого» — последняя строка таблицы с `**жирным**`, у которой первая ячейка пустая или сама жирная (`| | **Итого** | **1 460 000,00** | |`) → серая подложка.
- `> …` — выноска с синей линией слева.

### Шаг 3: Запустить конвертацию

Использовать скрипт конвертации:

```bash
bash <SKILL_DIR>/scripts/convert.sh -i INPUT.md -o OUTPUT.pdf -t ТЕМА [-l]
```

> `<SKILL_DIR>` — директория, в которую установлен скилл (например, `~/.claude/skills/md-to-pdf`).

Аргументы:
- `-i` — входной Markdown-файл (обязательно)
- `-o` — выходной PDF-файл (по умолчанию: то же имя с расширением `.pdf`)
- `-t` — название темы без префикса `theme-` (по умолчанию: `professional`)
- `-l` — landscape ориентация (по умолчанию: portrait)

### Шаг 4: Сообщить результат

- Показать путь к созданному PDF.
- Если конвертация упала — прочитать вывод ошибки и устранить проблему.

## Расположение CSS-тем

Все темы находятся в: `<SKILL_DIR>/assets/`

## Примечания

- Пайплайн: pandoc → HTML+CSS → Chrome headless → PDF
- Все темы поддерживают кириллицу (PT Sans, PT Serif, Fira Code)
- Для корректного отображения изображений они должны быть в той же папке, что и исходный файл, или использовать абсолютные пути
